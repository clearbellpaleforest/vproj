1. INTRO                                             *vproj-intro*

vproj is a project manager sidebar for Vim. Browse files, switch buffers,
and manage project structure from a vertical pane.

Press Tab to toggle the pane (temporary mode), Shift-Tab for permanent
mode, or use |:VprojToggle|. In temporary mode, the pane auto-closes when
you open a file, press ESC, or press Tab again. In permanent mode, the
pane stays open until you press Shift-Tab again or run |:VprojClose|.

Installation: clone the repository and run install.sh, or create symlinks
manually to ~/.vim/pack/bundle/start/vproj/.

2. COMMANDS                                         *vproj-commands*

:VprojToggle                                        *:VprojToggle*
    Toggle the project pane open (temporary mode) or closed.
    If the pane is open in permanent mode, switches to temporary.
    See |vproj-pane-modes|.

:VprojOpen                                          *:VprojOpen*
    Open the project pane.

:VprojClose                                         *:VprojClose*
    Close the project pane.

:VprojRefresh                                       *:VprojRefresh*
    Refresh the pane contents (re-read directory).

:VprojDiag                                          *:VprojDiag*
    Diagnostic tool. Tests split creation and reports window
    dimensions, cmdheight, and winmin settings. Useful for
    debugging E36 "Not enough room" errors.

:VprojCopy  :Copy                                  *:VprojCopy* *vproj-:Copy*
    Copy the file selected in the pane (file mode). The copy goes
    in the same directory under the first unused name of the form
    name_1.ext, name_2.ext, ...

:VprojDelete  :Delete                              *:VprojDelete* *vproj-:Delete*
    Delete the file selected in the pane (file mode), after a
    confirm prompt that defaults to No. The <Delete> key in the
    pane does the same.

:VprojRename  :Rename                              *:VprojRename* *vproj-:Rename*
    Rename the file selected in the pane (file mode). Prompts for
    the new name; the file stays in its directory. Refuses a name
    that already exists.

:VprojMove  :Move                                  *:VprojMove* *vproj-:Move*
    Move the file selected in the pane (file mode) to another
    directory. Prompts for the directory (with completion).
    Refuses if a file of that name already exists there.

    These four act on files only, not directories. Delete, Rename
    and Move refuse while the file has unsaved changes in a
    buffer. After Rename or Move, windows showing the file follow
    it to the new name.

    The short names :Copy :Delete :Rename :Move are defined only
    when no other plugin already defines them (vim-eunuch defines
    all four, for the current buffer's file). The :Vproj names
    always exist.

3. MODES                                             *vproj-modes*

File Mode  ([F]ile)                                 *vproj-mode-file*
    Browse the filesystem. Directories listed first, then files.
    File sizes shown for regular files. Press Enter on a
    directory to navigate into it, on a file to open it. Press
    . or <C-K> to go to the parent directory.

    Press T to toggle tree view (indented with expand/collapse).
    Press P to toggle a file preview split that updates on cursor move.
    Press / to filter by name pattern. Press * to grep the project
    and populate quickfix. Press <C-G> to toggle showing only
    git-changed files.

                                               *vproj-tree-view*
    Tree view toggles between flat listing and an indented directory
    tree with expand/collapse within file mode.

                                               *vproj-preview*
    File preview shows file contents in a split that updates as the
    cursor moves. Press P again to close.

                                               *vproj-filter*
                                               *vproj-grep*
    Filter (/) narrows the listing by name pattern. Grep (*) runs
    `git grep` (case-insensitive) over the repository, or over the
    pane's directory outside a repository, and fills the quickfix
    list for |vproj-mode-qfix|.

Buf Mode  ([B]uf)                                   *vproj-mode-buf*
    Switch between open buffers. Modified buffers marked with +,
    current buffer marked with %. Press X to close a buffer.
    Line counts shown.

Code Mode  ([C]ode)                                 *vproj-mode-code*
    Project-aware file tree from a .vproj file. Included items
    shown normally; excluded items shown in parentheses.
    Press + or - to toggle inclusion. Press Enter on the
    status line to rename or create the project.

    Git actions (\s, \d, \D, \c, \p, \u, \b, \z,
    \Z, \a, <C-G>) use a backslash prefix in both File and Code modes.

                                               *vproj-git-actions*
    Git actions work in file and code modes via \(bslash) prefix.
    Stage (\s) stages worktree changes and untracked files
    (`git add`); on a file whose changes are only staged it unstages
    them. Diff preview (\d) opens a vertical split with the file's
    diff (staged, unstaged or both); the cursor stays in the pane, so
    move to the diff window (CTRL-W w) and press q there, or use
    :close. Discard
    (\D) asks first and says what it will do: delete an untracked
    file, unstage a newly added file (the file is kept), or revert
    every staged and unstaged change to HEAD. Commit (\c) prompts
    for a message. Push (\p), pull (\u), and branch switch (\b)
    use prompts for target/confirmation; push and pull never stop to
    ask for credentials (they fail instead).

                                               *vproj-git-stash*
    Stash (\z) pushes current changes with an optional message via
    `git stash push`. Stash pop (\Z) lists all stashes first, then
    prompts for which to pop (default: top). Both operate on the
    whole repository.

                                               *vproj-git-blame*
    Blame (\a) opens a vertical split showing `git annotate` output
    for the file under cursor. Requires the file be tracked by git.
    The cursor stays in the pane: move to the blame window (CTRL-W w)
    and press q there, or use :close.

Qfix Mode  ([Q]fix)                                 *vproj-mode-qfix*
    Displays the Vim quickfix list. Press Enter to open the
    selected entry at the file and line number.

Press <Up> on the first item to reach the mode menu line (line 1),
then Enter to cycle through modes.
Press Shift-F, Shift-B, or Shift-C inside the pane to switch
directly. Press Q in temporary mode to switch to qfix; in permanent
mode to close the pane.

4. KEY MAPPINGS                                    *vproj-mappings*

All mappings are buffer-local to the VPROJ pane. They do not affect
other buffers.

Navigation:
    <Down> / <Up>       Move selection down / up
    Enter               Open file or enter directory
    .                    Go to parent directory (file and code mode)
    <C-K>               Go to parent directory
    <C-J>               Enter first subdirectory
    <C-T>               Jump to first item
    <C-B>               Jump to last item

Mode switching:
    Shift-F              File mode
    Shift-B              Buf mode
    Shift-C              Code mode
    Q                    Qfix mode (temporary) / Close pane (permanent)

Git actions — backslash prefix (file and code modes):
    \s                  Stage / unstage file under cursor
    \d                  Open diff preview in vertical split
    \D                  Discard file changes (with confirmation)
    \c                  Commit with message prompt
    \p                  Push to remote
    \u                  Pull --ff-only from remote
    \b                  Switch branch (with prompt)
    \z                  Stash changes (optional message)
    \Z                  Pop a stash (shows list, select by index)
    \a                  Blame file under cursor (git annotate)
    <C-G>               Toggle showing only git-changed files

Actions:
    Shift-R              Refresh listing
    Shift-X              Close selected buffer (buf mode)
    <Delete>            Delete selected file (file mode, confirms)
    + / -               Include / exclude item (code mode)
    Shift-T              Toggle tree view (file mode)
    Shift-P              Toggle file preview split
    /                   Filter files by name pattern
    *                   Grep project and populate quickfix
    <Left> / <Right>    Shrink / grow pane width
    <F1>                Toggle info column
    ?                   Show a key reference in a help window (q closes it)

Cursor motions:
    Vim motions such as 0 $ ^ % { } ( ) <C-D> <C-U> and a mouse click move
    the cursor as usual, but the cursor is kept on an item row (or the mode
    menu): G, L and <C-F> end on the last item, never on the page footer, and
    the separator row is skipped. "gg" does not work, because g is a nav
    letter: use <C-T> (first item) and <C-B> (last item).

    When the pane is the only window left (the edit window was closed), Vim
    quits as it would on the last real window; a modified buffer still stops
    it (E37, E162).

Quick Nav:                                       *vproj-nav-char*
    >                   Letter the next 26 items (more than 26 shown)
    <                   Letter the previous 26 items
    a–z                 Jump to item by nav character

    Nav characters are the colored single letters on each line.
    Press the matching letter to jump directly to that item. In
    file and code mode, nav characters open files or enter
    directories. In buf and qfix mode, they move the cursor
    without opening files.

                                               *vproj-paging*
Paging:
    <C-N>               Next page
    <C-P>               Previous page

Close:
    Q (perm mode)        Close pane
    Esc                 Close pane (temporary mode only)

Global (outside pane):
    <Tab>               Open pane (temporary mode, auto-closes)
    <S-Tab>             Open pane (permanent mode, stays open)

    The default <Tab> and <S-Tab> mappings are not defined when you already
    map that key in Normal mode when the plugin loads; your mapping stays.
    To use the pane with such a key anyway, map it yourself:
>
        nmap <Tab> <Plug>VprojToggle
<
Pane Modes:                                      *vproj-pane-modes*
    Temporary mode (Tab): The pane auto-closes when you open a file,
    press Esc in the pane, or press Tab again. This mode is for
    quick file/buffer access — no extra keystroke to dismiss.

    Permanent mode (Shift-Tab): The pane stays open until you press
    Shift-Tab again, press Q (with the pane focused), or close
    the pane buffer via |:bdelete|. This mode is for extended project
    management sessions.

    Pressing the alternate toggle key while the pane is open
    transitions between modes without closing the pane.

                                                 *vproj-session*
Session:
    Off by default: vproj writes no files on its own. With
    g:vproj_save_session = 1 it saves its mode, directory, width,
    info column and git filter to $XDG_CACHE_HOME/vproj/session
    (~/.cache/vproj/session when unset) when the pane closes, and
    restores them the next time the pane opens. The previous file is
    kept as session.bak. An existing session file is read on open
    whether or not saving is on.

                                               *vproj-troubleshooting*
Troubleshooting ~

                                               *vproj-cmdheight*
    E36 "Not enough room" on split ~
        If you see E36 "Not enough room" when opening files, blame,
        or diffs from the pane, check your command-line height:
>
            :set cmdheight?
<
        If the value is unusually high (above 2), Vim may not have
        enough window space to create vertical splits. Lower it:
>
            :set cmdheight=1
<
        Or set it permanently in your vimrc:
>
            set cmdheight=1
<
        Some terminal emulators and multiplexers configure high
        cmdheight values automatically. vproj temporarily lowers
        cmdheight, winminwidth, and winminheight during split
        operations to prevent E36, but persistent high values can
        still cause issues in edge cases.

        If the problem persists, run |:VprojDiag| to see current
        window dimensions and option values.

Example vimrc:
>
    " Remap temporary toggle to F2
    nmap <F2> <Plug>VprojToggle
    nunmap <Tab>

    " Remap permanent toggle to F3
    nmap <F3> <Plug>VprojTogglePermanent
    nunmap <S-Tab>
<

6. .vproj FILE FORMAT                             *vproj-file-format*

The .vproj file defines a project for Code mode. It lives at the
project root.

Format: >

    Project Name: my-project
    Project Root: /home/user/dev/my-project
    Included Directories:
    src
    Included Files:
    README.md
    Excluded Directories:
    .git
    node_modules
    Excluded Files:
    .env

Lines starting with # before the first list section are comments;
they are kept when vproj saves the file. Inside a list section a
leading # is part of the name.

Project Root may be empty, which means the directory holding the
.vproj file, or relative to that directory. If the root does not
exist, vproj matches against the .vproj directory and leaves the
line unchanged when it saves.

A trailing / on a directory entry is ignored ("src/" is "src"). An
entry containing * or ? is a glob, matched against the path and
against the last name: "*.swp" excludes every .swp file. [ and ]
are ordinary characters, so "[id].tsx" names exactly that file.

Only * and ? are special in an entry; { } , $ ^ and \ are ordinary
characters. A file cannot be included or excluded (+ and -) when its
name cannot be stored in the .vproj file: a name with * or ?, blanks at
either end, a control character or U+FEFF, or one that starts like a
section header ("Included Files: x"). vproj refuses it and leaves the
file unchanged.

AI ASSISTANT                                  *vproj-ai* *vproj-ai-setup*

Press A in the vproj pane to open an AI chat terminal. The AI can answer
questions about your code or apply code directly to your file.

                                                 *g:vproj_ai_api_key*
API Key ~

Set your API key via one of:
  let g:vproj_ai_api_key = 'sk-...'          in your vimrc
  $DEEPSEEK_API_KEY                           environment variable
  $OPENAI_API_KEY                             environment variable

The default API endpoint is api.deepseek.com. To use a different provider:
  let g:vproj_ai_api_url = 'https://...'

                                                 *g:vproj_ai_model*
Model ~

The model is auto-selected based on the endpoint. Override if needed:
  let g:vproj_ai_model = 'deepseek-chat'

                                                 *:VprojAiPrompt*
Commands ~

  :VprojAiPrompt [prompt]      One-shot AI prompt (streams to code or popup)
  <Plug>VprojAiPrompt          Mapping indirection for custom keybindings
                                                 *:VprojAgent*
  :VprojAgent                  Open your coding-agent CLI in a terminal split
  <Plug>VprojAgent             Mapping for :VprojAgent. No default key:
                               e.g. nmap <Leader>a <Plug>VprojAgent

                                                 *g:vproj_agent_cmd*
By default :VprojAgent runs the first official agent CLI found on PATH:
claude (npm install -g @anthropic-ai/claude-code), then codex
(npm install -g @openai/codex). To run another agent, name it:
  let g:vproj_agent_cmd = 'myagent'               program on PATH
  let g:vproj_agent_cmd = ['myagent', '--flag']   program and arguments
If the configured program cannot run, :VprojAgent reports it and runs
nothing else.

The agent receives the current file context through $VPROJ_AGENT_CTX_FILE,
the path of a private (0600) file that is deleted when the agent exits.
Esc in the agent terminal goes to the agent; the split closes when the
agent exits.

Usage ~

- Press A in the vproj pane → opens a terminal chat
- Type your prompt and press Enter
- The AI streams its response in real time
- Code mode (default) inserts the first fenced code block of the response
  into your file below the cursor, only after you confirm (Esc = No). A
  response without a fenced block is shown in a popup, never inserted.
- Question mode shows the response in a popup. A prompt is a question when
  it starts with a question word (what, how, why, explain, ...) or ends with
  ?; a prompt that starts with a code verb (add, write, fix, ...) is code
  even if it contains a question word or ? later. Start the prompt with !
  to force code mode, or with ? to force question mode.
- Ctrl-D or /exit to quit the chat
- Ctrl-C to cancel a streaming response
